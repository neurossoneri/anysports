# Сайт консультанта: интуиция в спорте

Репозиторий для **GitHub Pages + Pages CMS**. Одностраничный лендинг без шаблонов продаж: большая фотография, рукописные цитаты, мягкие формы, рваный ритм, один язык (English). Общий замысел и принципы — в [`docs/CONCEPT.md`](docs/CONCEPT.md). Если меняется идея сайта, сначала правим этот файл.

- **Сайт:** GitHub Pages, статический хостинг без базы данных.
- **Редактор:** личный кабинет `/admin/` (основной) и [Pages CMS](https://app.pagescms.org/) (запасной, статьи): изменения сохраняются в этом репозитории.
- **Публикация:** GitHub Actions собирает HTML и обновляет GitHub Pages после каждого изменения в `main`.

> В корне репозитория нет вручную обновляемого `index.html`. Разметка лежит в `templates/index.html`, а рабочий `index.html`, страницы статей и всё остальное создаёт `scripts/build.py`. В настройках Pages выбирайте источник **GitHub Actions**, а не «Deploy from a branch».

## 0. Название сайта и панель управления

- **Название — Sport Intuitive.** Оно задаётся полем «Название сайта (бренд)» (`brand` в `content/site.json`) и применяется в шапке, во вкладке браузера, в подвале, в превью ссылок и на страницах статей. Личное имя автора остаётся отдельным полем и показывается в подвале рядом с названием.
- **Личный кабинет — `/admin/`** (например, `https://ваш-сайт/admin/`). Вкладки: **Фотографии** (7 нумерованных мест, загрузка перетаскиванием, автоматическое сжатие), **Тексты** (English, поиск по полям), **Название и контакты**, **Публикация** (индексация, статус сборки). Все правки сохраняются одним коммитом в GitHub, сайт пересобирается сам. Подробная инструкция для владелицы: [`docs/DASHBOARD.md`](docs/DASHBOARD.md).
- **Номера фото на сайте:** откройте сайт с `?photos` в конце адреса (`https://ваш-сайт/?photos`). На каждом фото появится жёлтая метка «Фото 1…7», такая же, как в панели.
- Pages CMS остаётся запасным редактором и местом для статей. Поля в `.pages.yml` пронумерованы так же, как в панели.
- Список полей панели строится при сборке из `.pages.yml` (файл `_site/admin/schema.json`). Добавили поле в CMS и в JSON, оно само появится в панели.
- Перед сохранением панель проверяет то же, что и тесты: запрещённые формулировки-обещания и обязательные поля. Эти списки лежат в `scripts/build.py` (`BANNED_PHRASES`, `REQUIRED_COPY`).

## 1. Первоначальная установка (один раз)

1. Репозиторий на GitHub, основная ветка `main`.
2. **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. Вкладка **Actions** → **Build and deploy GitHub Pages**. Первый push в `main` запускает сборку. При необходимости нажмите **Run workflow**.
4. Дождитесь зелёного статуса. Адрес сайта появится в **Settings → Pages**.
5. Откройте <https://app.pagescms.org/>, войдите через GitHub, установите приложение для **этого** репозитория и выберите `main`. Редактор сам прочитает `.pages.yml`.

## 2. Что редактируется без кода

| Раздел в Pages CMS | Что внутри |
|---|---|
| **Контакты, фото, имя** | Имя и специализация, email, WhatsApp, Telegram, **адрес формы связи**, все фотографии, адрес сайта, «готов к индексации» |
| **Тексты сайта (English)** | Все тексты страницы. Они сгруппированы в том же порядке, в каком идут на сайте: главный экран, введение, интуитивные сессии, трансформация, обо мне, контакты и форма, Q&A (в конце блок «вводная беседа бесплатно»), заметки, подвал |
| **Статьи / Articles** | Короткие тексты («Заметки»). Раздел «Заметки» на главной появляется **только когда опубликована хотя бы одна статья** |
| **Media** | Загрузка фотографий |

### Цитаты

Три цитаты находятся в группе **«Цитаты»**: во введении (рядом с фото), в «Интуитивных сессиях» и в «Трансформации». Они проявляются на экране «от руки», когда посетитель до них долистывает. Перенос строки в поле — это перенос строки в цитате. Цитаты **Б** и **В** теперь взяты из вашей презентации; проверьте формулировки (см. `docs/CONTENT-REVIEW.md`).

### Q&A

Восемь слотов в трёх группах (подписи групп тоже редактируются). Чтобы убрать вопрос, **очистите поле вопроса**: слот исчезнет с сайта; группа без вопросов скрывается целиком. Блок «An introductory conversation costs you nothing» стоит под вопросами.

### Фотографии

Все поля находятся в **Контакты, фото, имя**:

| Поле | Где показывается |
|---|---|
| Главное фото | Крупное фото слева на первом экране (с 24 октября; раньше было справа) и картинка для соцсетей |
| Обо мне · фото 1–4 | Мозаика справа от текста «Обо мне» |
| Фото крупным планом (№ 3) | Рядом с «Интуитивными сессиями». Если пусто, место остаётся пустым: главное фото сюда больше не подставляется |

Пока фотографии нет, на её месте мягкая заготовка. Форматы JPG/WebP/AVIF; для кадров истории подойдёт вертикаль примерно 3:4 или 4:5, для главного фото — горизонталь или вертикаль, обрезка по центру. Не добавляйте в публичный репозиторий приватные материалы клиентов.

## 3. Форма связи (письма приходят на почту)

GitHub Pages — статический хостинг, поэтому письма отправляет внешний сервис форм. Он принимает сообщение с сайта и пересылает его на вашу почту. Нужен один адрес, **ничего не вставляется в код**.

**Вариант 1. Formspree** (адрес почты не виден на сайте).
1. Зарегистрируйтесь на <https://formspree.io/>, создайте форму и укажите свою почту.
2. Скопируйте адрес вида `https://formspree.io/f/xxxxxxxx`.
3. Pages CMS → **Контакты, фото, имя** → **Адрес формы связи** → вставьте адрес → сохраните.

**Вариант 2. FormSubmit** (без регистрации). Адрес: `https://formsubmit.co/ajax/ВАШ_EMAIL`. При первой отправке придёт письмо с подтверждением: подтвердите его один раз. Минус: почта окажется в адресе формы, то есть в коде страницы, и её могут собрать спам-боты.

Что делает форма:
- Посетитель указывает имя, способ связи (email, Telegram или WhatsApp) и, если хочет, пару слов. Если он оставил email, ответ в письме можно отправить кнопкой «Ответить».
- Скрытое поле-ловушка отсеивает ботов.
- Если адрес формы ещё не задан, но указан email, форма откроет у посетителя почтовую программу с готовым письмом. Если нет ни того ни другого, она вежливо попросит написать напрямую.
- Адрес формы должен начинаться с `https://`, иначе сборка проигнорирует его и напишет предупреждение в лог.

Данные посетителя проходят через стороннего оператора форм. Под формой стоит согласие со ссылкой на страницу `privacy/` (политика конфиденциальности по швейцарскому закону о защите данных, FADP). Перед запуском проверьте, что выбранный сервис форм есть в списке Swiss-U.S. Data Privacy Framework (dataprivacyframework.gov) либо заключите с ним договор об обработке данных (DPA) со стандартными договорными положениями. Текст политики правится в Pages CMS → «Политика конфиденциальности».

## 4. Добавление статьи

1. Pages CMS → **Статьи / Articles** → **New**.
2. Заголовок, **URL slug** (латиница и дефисы), язык, дата, анонс, при желании категория и обложка.
3. Текст в визуальном редакторе. Включите **Опубликовано** только когда текст готов.
4. После сборки появятся отдельная страница, архив выбранного языка и раздел «Заметки» на главной.

Сайт одноязычный: у статей `lang=en`. В комплекте есть одна неопубликованная демонстрационная статья.

## 5. Контакты и готовность к индексации

- WhatsApp: номер только цифрами, с кодом страны, без `+`: `491234567890`.
- Telegram: username без `@`.
- Public site URL: можно оставить пустым для обычного GitHub Pages. Для своего домена укажите полный HTTPS-адрес.

**Безопасный старт:** пока включено `publish_ready: false`, страницы закрыты от поисковиков (`noindex`, `robots.txt`). Когда имя, фотографии и тексты проверены, включите **Готов к индексации** и сохраните. Сайт при этом доступен по ссылке в любом режиме.

## 6. Структура кода

```text
docs/CONCEPT.md            Замысел сайта: принципы, порядок блоков, язык движения
.pages.yml                 Формы редактора Pages CMS
.github/workflows/deploy.yml  Сборка и публикация
content/
  site.json                Имя, контакты, адрес формы, фотографии
  home_en.json             Тексты главной (сгруппированы по блокам)
  privacy.md               Политика конфиденциальности (страница privacy/)
  posts/*.md               Статьи
media/                     Загруженные фотографии
scripts/build.py           Генератор HTML
scripts/test_build.py      Проверки
templates/index.html       Разметка, стили и скрипт главной (без текстов)
requirements.txt           Зависимости Python
```

В шаблоне нет текстов: у каждого элемента атрибут `data-i18n="группа.ключ"`, а сам текст берётся из `content/home_*.json`. Короткие служебные подписи (подсказки для скринридеров, сообщения формы, названия тем) лежат в словаре `UI` в `scripts/build.py`. Тест `scripts/test_build.py` проверяет, что для каждого ключа шаблона есть текст и что `.pages.yml` совпадает с JSON-файлами. Если вы добавили поле только в одном месте, сборка в GitHub Actions остановится и покажет, где именно.

## 7. Проверка локально (необязательно)

```bash
python -m pip install -r requirements.txt
python scripts/build.py
python scripts/test_build.py
```

Результат — `_site/index.html`. Для обычной работы через CMS локальные команды не нужны.

## 8. Что нужно знать

- На GitHub Pages нет PHP, базы данных и закрытой админки: редактор меняет файлы в GitHub, а Actions публикует статический результат.
- Изменения видны после успешного завершения workflow, обычно через минуту-две.
- Не редактируйте `_site/`: сборка перезаписывает его.
- Анимации отключаются при `prefers-reduced-motion`: цитаты просто показываются сразу. Без JavaScript страница остаётся читаемой.
- После публикации проверьте сайт на телефоне, ссылки, форму (отправьте себе тестовое сообщение) и юридические требования вашей страны.

Документация: [Pages CMS](https://pagescms.org/docs/quick-start/), [GitHub Pages custom workflows](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## 9. Дизайн: токены и формы

Весь CSS в одном блоке `<style>` файла `templates/index.html`. Цвета заданы переменными в начале. Фоны секций: `--abyss`, `--deep`, `--teal` (тёмные) и `--sand`, `--dune` (светлые, тёплый песок); акценты синий и зелёный. Углы фото, плашек и секций прямые; кнопки, поля формы и «+» мягкие. Тест разрешает `border-radius` только у кнопок и полей. Подкраска фото (`--photo-grade`) убрана: она была выключена и только нагружала прокрутку. Переключателя светлой и тёмной темы на главной больше нет: тон секций задают фоны (`.band-deep`, `.band-teal`, `.band-sand`, `.band-dune`); тема остаётся только на страницах статей.

Логотип и favicon — встроенный SVG в `templates/index.html`; `scripts/build.py` подставляет их и на страницы статей.

Выделенную фразу можно очистить в CMS: она исчезнет.
- **Тёплый песок.** `--sand #e5dac4`, `--dune #dccfb4` вместо холодных светло-серых. Переходы из тёмных цветов в песок рассчитаны в цветовом пространстве OKLab и в середине чуть теплеют, поэтому нет холодной серо-белой дымки. Длина перехода: `--blend`.
- **Чистка после прошлого обновления:** убраны упоминания RU/FR и FAQ в README и docs.

## Обновление: плавная прокрутка, фото по номерам, простая панель (24 октября 2026)

Применено скриптом `apply_smooth_photos_update.py`.

- **Каждое фото на своём месте.** Мест семь, у каждого свой номер и своё поле в «Контакты, фото, имя». Раньше пустое место 3 («крупный план») подставляло главное фото 1, и оно повторялось ниже по странице: подстановку убрали. Пустое место остаётся пустым. Пока сайт закрыт от поисковиков, на нём жёлтый номер; после включения «Показывать поисковикам» пустое место скрывается вместе с рамкой, и страница сама закрывает просвет.

- **Куда загружать фото.** В папку `media/`. Проще всего через панель `/admin/` → «Фотографии» → «Заменить»: фото сожмётся и получит имя вида `media/photo-3-<дата>.webp`. Вручную: положите файл в `media/` (например `media/photo-3.jpg`) и впишите путь в Pages CMS → «Контакты, фото, имя» → «Фото 3». Другие папки сборка не копирует.
- **Плавная прокрутка.** Что было тяжёлым и что сделано: (1) каждая буква рукописных цитат анимировала размытие и обрезку (сотни элементов сразу), теперь только прозрачность и сдвиг; (2) итоговые фразы больше не проявляются через размытие; (3) убрана выключенная «подкраска фото» (`--photo-grade`): она вешала фильтр и два слоя смешивания на каждое фото; (4) вне экрана «отдыхает» только бабочка, а не целые секции (раньше при каждом переключении браузер пересчитывал стили всех элементов секции), у бабочки свой слой; (5) полоса прокрутки в браузерах без scroll-driven animations больше не измеряет страницу на каждое событие прокрутки; (6) тексты, уже записанные сборкой, скрипт не переписывает; (7) шрифт рукописных цитат подгружается заранее, страница не «прыгает», когда он приходит; (8) убраны `text-rendering:optimizeLegibility` и размытие фона у кнопок. Нативная прокрутка браузера сохранена намеренно: скрипты «плавного скролла» сами добавляют рывки.
- **Страховка.** Если скрипт страницы по какой-то причине не запустился, через 5 секунд страница показывает себя без анимаций, а не остаётся пустой.
- **Лёгкие копии фото.** Если на сборке установлен Pillow (он в `requirements.txt`, GitHub Actions ставит его сам), для каждого фото создаются копии шириной 640, 1080 и 1600 пикселей (WebP) в `media/opt/` (только на сайте, в репозиторий они не попадают), и браузер берёт подходящую: телефон не скачивает мегабайты оригинала. Оригинал остаётся как есть. Без Pillow сайт работает по-прежнему, только без копий.
- **Панель.** Плоское тихое оформление: светлый фон, тонкие линии, одна тёмная кнопка, без теней, градиентов и плавающих плашек. «Фотографии» — простой список из семи строк: номер, миниатюра, «Заменить» / «Убрать» / «Вернуть». Схема страницы и блок «Загрузить по номеру» убраны; несколько файлов с номерами в названии (`1.jpg`, `фото-3.png`) по-прежнему можно перетащить на список.

# Сайт консультанта

Готовый репозиторий для **GitHub Pages + Pages CMS**. Основан на согласованном HTML-дизайне: стеклянные панели, бело-голубые/мятные градиенты, тёмно-синяя тема, мобильная адаптация, квиз, отзывы рукописным шрифтом и три языка (RU/EN/FR).

- **Сайт:** GitHub Pages — статический хостинг без базы данных.
- **Редактор:** [Pages CMS](https://app.pagescms.org/) — вход через GitHub, изменения сохраняются в этом репозитории.
- **Публикация:** GitHub Actions автоматически генерирует HTML и обновляет GitHub Pages после изменения контента.
- **Стоимость инфраструктуры:** можно использовать бесплатные тарифы для публичного репозитория в пределах правил и лимитов сервисов; собственный домен необязателен.

> Важное отличие: в корне репозитория **не нужен вручную обновляемый `index.html`**. Исходный дизайн находится в `templates/index.html`. Рабочий `index.html`, страницы статей и всё остальное создаются скриптом `scripts/build.py` и автоматически публикуются через GitHub Actions. Не включайте режим Pages «Deploy from a branch» — используйте «GitHub Actions».

## 1. Первоначальная установка (один раз)

1. Создайте новый репозиторий на GitHub, например `athlete-support-site`. Для типового бесплатного GitHub Pages используйте **Public**. Основная ветка — **main**.
2. Распакуйте архив. Загрузите **содержимое архива** в корень репозитория, сохранив папки и скрытые файлы `.pages.yml` и `.github/workflows/deploy.yml`. Надёжнее всего это сделать Git-клиентом или GitHub Desktop. Не загружайте всю папку проекта как одну вложенную папку.
3. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. Откройте вкладку **Actions**, найдите **Build and deploy GitHub Pages**. Первый push в `main` запускает сборку автоматически. При необходимости запустите **Run workflow** вручную.
5. Дождитесь зелёного статуса workflow. Адрес сайта появится в **Settings → Pages**. Обычный формат: `https://ACCOUNT.github.io/REPOSITORY/` (для репозитория `ACCOUNT.github.io` путь иной).
6. Откройте **https://app.pagescms.org/**, войдите с GitHub и установите GitHub App для **этого репозитория**. Разрешения выдавайте только нужному репозиторию. Выберите `main`: редактор автоматически прочитает `.pages.yml` и предложит формы.

Важно: Pages CMS — отдельный редактор, авторизованный через GitHub. Он **не** размещается на самом GitHub Pages и не требует хранить персональный access token в HTML. Изменения происходят прямо в файлах репозитория и запускают GitHub Actions.

## 2. Что редактируется без кода

В редакторе Pages CMS доступны:

| Раздел | Что можно менять |
|---|---|
| Контакты, фото, имя / Site settings | Имя и специализацию на RU/EN/FR; email, WhatsApp, Telegram, ссылку на запись; портрет и три дополнительные фотографии; адрес сайта; готовность к индексации |
| Тексты главной (RU), Homepage text (EN), Textes d'accueil (FR) | Главный экран, описания направлений, тексты обо мне, подтверждённую квалификацию, вступление в блог, описание отзывов, вопросы и ответы, контактные формулировки |
| Отзывы / Testimonials | Добавлять, удалять и скрывать текстовые отзывы на трёх языках; отдельно задавать подпись автора (только по согласованию) |
| Статьи / Articles | Создавать/редактировать статьи с заголовком, анонсом, датой, категорией, обложкой, форматированным текстом, языком и статусом публикации |
| Media | Загружать фотографии в репозиторий и выбирать их из полей редактора |

Интерфейсные подписи («Вперёд», «Назад», названия кнопок квиза и т. п.) локализованы в исходном HTML; наиболее важные **содержательные** тексты доступны в CMS. Если потребуется менять абсолютно все системные микротексты, они находятся в `templates/index.html`.

## 3. Добавление статьи

1. Pages CMS → **Статьи / Articles** → **New**.
2. Заполните **Заголовок**, **URL slug** латинскими строчными буквами и дефисами (`how-to-handle-pressure`), **Язык** (RU/EN/FR), **Дата**, **Анонс**, при необходимости **Категория** и **Обложка**.
3. Напишите статью в визуальном редакторе **Текст статьи / Article body**. Можно вставлять изображения через Media.
4. Включите **Опубликовано / Published**, только когда текст готов. Сохраните. Pages CMS сохранит файл Markdown в `content/posts/`.
5. GitHub Actions автоматически создаст отдельную страницу, например `https://ACCOUNT.github.io/REPOSITORY/ru/articles/how-to-handle-pressure/`, и карточку в блоге лендинга. Автоматически обновится архив статей выбранного языка.

**Переводы статей — отдельные записи.** Для статьи на английском создайте отдельную запись с `lang=en`; для французской — с `lang=fr`. Сайт не генерирует машинный перевод, а отображает только реально подготовленные публикации соответствующего языка. Названия и описания не смешиваются.

В комплекте лежит **одна демонстрационная статья-черновик** (`sample-ru.md`, `published: false`). Она не публикуется до ручного включения.

## 4. Фотографии

Pages CMS → **Media** → Upload или кнопка выбора изображения прямо внутри настроек сайта / статьи. После загрузки сохраните поле, чтобы в JSON появилась ссылка вида `media/portrait.webp`. Сам файл хранится в `media/` в репозитории.

Рекомендации: JPG/WebP/AVIF, оптимизированные изображения; портрет в вертикальном формате примерно 4:5, остальные снимки по смыслу секций. Лучше использовать реальные профессиональные кадры и заранее получить разрешения на публикацию чужих лиц. **Не добавляйте приватные материалы клиентов** в публичный репозиторий.

## 5. Контакты и готовность к индексации

Pages CMS → **Контакты, фото, имя / Site settings**.

- WhatsApp: международный номер **только цифрами**, например `491234567890`, без `+`, пробелов и скобок.
- Telegram: публичный username **без** символа `@`.
- Email: обычный адрес, например `hello@example.com`.
- Booking URL: реальный адрес `https://...`.
- Public site URL: можно оставить пустым для стандартного GitHub Pages (определяется автоматически во время Actions). При подключении своего домена задайте **полный HTTPS-адрес сайта**. Это значение участвует в canonical/sitemap, но **не создаёт и не привязывает домен самостоятельно**.

**Безопасный старт:** `publish_ready: false` по умолчанию добавляет `noindex` на страницы и ограничивает индексацию через `robots.txt`. Когда тексты, имя, квалификация, фотографии и согласованные отзывы заполнены, переключите **Готов к индексации / Allow search indexing** в `true` и сохраните. Тогда сборка создаст `sitemap.xml` и разрешит индексирование. Публикация сайта в браузере работает в обоих режимах: этот переключатель влияет **только на поисковые системы**, а не на доступность URL.

**Отзывы:** загружайте только подлинные текстовые отзывы, для которых получено разрешение на публикацию; не создавайте фиктивные аккаунты, атрибуцию или результаты. Если отзывов нет, сайт показывает нейтральное пояснение, а не вымышленные цитаты.

## 6. Кодовая структура

```text
.pages.yml                 Настройка UI редактора Pages CMS
.github/workflows/deploy.yml  Автоматическая сборка и публикация
content/
  site.json                Имя, контакты, фото и параметры
  home_ru.json             Тексты главной на русском
  home_en.json             Тексты главной на английском
  home_fr.json             Тексты главной на французском
  reviews.json             Отзывы
  posts/*.md               Markdown-статьи (опубликованные и черновики)
media/                     Фотографии из редактора
scripts/build.py           Генератор HTML
scripts/test_build.py      Проверки конфигурации/генератора
templates/index.html       Последняя согласованная версия дизайна
requirements.txt           Зависимости Python
```

При сборке формируется `_site/` (в Git не хранится), в том числе `index.html`, `assets/`, `ru/articles/`, `en/articles/`, `fr/articles/`, `robots.txt`, при готовности сайта — `sitemap.xml`.

## 7. Проверка локально (необязательно)

Нужен Python 3.12+; из корня репозитория:

```bash
python -m pip install -r requirements.txt
python scripts/build.py
python scripts/test_build.py
```

Готовый сайт — в `_site/index.html`. Для обычной работы через CMS **никакие локальные команды не нужны**.

## 8. Что нужно знать

- GitHub Pages **не содержит PHP, базы данных и закрытого административного раздела**. Редактор управляет файлами в GitHub, а Actions публикует статический результат.
- Это публикационный сайт, не приложение для хранения персональных запросов посетителей. Квиз остаётся на стороне браузера. Формы сбора чувствительных данных намеренно нет.
- Изменения сайта становятся видны после завершения очередного успешного GitHub Actions workflow (обычно не мгновенно).
- Не редактируйте сгенерированные файлы в `_site/`: их перезаписывает сборка. Вносите изменения через CMS или в `templates/index.html`.
- Приоритеты локализации: все меню/кнопки есть на RU/EN/FR; статьи и отзывы появляются только при наличии соответствующего перевода. Главная страница единая, с клиентским переключением языка; отдельные URL статей используют языковые пути.
- После публикации проверьте фактический сайт на мобильном устройстве, корректность ссылок, доступность контента и юридические требования вашей страны.

Официальная документация: [Pages CMS](https://pagescms.org/docs/quick-start/), [GitHub Pages custom workflows](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

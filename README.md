# Сайт консультанта: интуиция в спорте

Репозиторий для **GitHub Pages + Pages CMS**. Одностраничный лендинг без шаблонов продаж: большая фотография, рукописные цитаты, мягкие формы, рваный ритм, три языка (RU/EN/FR). Общий замысел и принципы — в [`docs/CONCEPT.md`](docs/CONCEPT.md). Если меняется идея сайта, сначала правим этот файл.

- **Сайт:** GitHub Pages, статический хостинг без базы данных.
- **Редактор:** [Pages CMS](https://app.pagescms.org/): вход через GitHub, изменения сохраняются в этом репозитории.
- **Публикация:** GitHub Actions собирает HTML и обновляет GitHub Pages после каждого изменения в `main`.

> В корне репозитория нет вручную обновляемого `index.html`. Разметка лежит в `templates/index.html`, а рабочий `index.html`, страницы статей и всё остальное создаёт `scripts/build.py`. В настройках Pages выбирайте источник **GitHub Actions**, а не «Deploy from a branch».

## 1. Первоначальная установка (один раз)

1. Репозиторий на GitHub, основная ветка `main`.
2. **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. Вкладка **Actions** → **Build and deploy GitHub Pages**. Первый push в `main` запускает сборку. При необходимости нажмите **Run workflow**.
4. Дождитесь зелёного статуса. Адрес сайта появится в **Settings → Pages**.
5. Откройте <https://app.pagescms.org/>, войдите через GitHub, установите приложение для **этого** репозитория и выберите `main`. Редактор сам прочитает `.pages.yml`.

## 2. Что редактируется без кода

| Раздел в Pages CMS | Что внутри |
|---|---|
| **Контакты, фото, имя** | Имя и специализация (RU/EN/FR), email, WhatsApp, Telegram, **адрес формы связи**, все фотографии, адрес сайта, «готов к индексации» |
| **Тексты сайта · русский / English / Français** | Все тексты страницы. Они сгруппированы в том же порядке, в каком идут на сайте: главный экран, введение, интуитивные сессии, трансформация, обо мне, контакты и форма, вопросы и ответы (с блоком «30 минут бесплатно»), заметки, подвал |
| **Статьи / Articles** | Короткие тексты («Заметки»). Раздел «Заметки» на главной появляется **только когда опубликована хотя бы одна статья** |
| **Media** | Загрузка фотографий |

### Цитаты

Три цитаты находятся в группе **«Цитаты»**: во введении (рядом с фото), в «Интуитивных сессиях» и в «Трансформации». Они проявляются на экране «от руки», когда посетитель до них долистывает. Перенос строки в поле — это перенос строки в цитате. Цитаты **Б** и **В** теперь взяты из вашей презентации; проверьте формулировки (см. `docs/CONTENT-REVIEW.md`).

### Вопросы и ответы

Восемь слотов (7 и 8 пока пустые и скрыты: туда можно добавить вопросы про стоимость, формат, конфиденциальность). Чтобы убрать вопрос, **очистите поле вопроса**: слот исчезнет с сайта. Чтобы добавить, заполните пустой слот.

### Фотографии

Все поля находятся в **Контакты, фото, имя**:

| Поле | Где показывается |
|---|---|
| Главное фото | Крупное фото слева на первом экране и картинка для соцсетей |
| Обо мне · фото 1–4 | Мозаика справа от текста «Обо мне» |
| Фото крупным планом | Рядом с «Интуитивными сессиями». Если пусто, берётся главное фото |

Пока фотографии нет, на её месте мягкая заготовка. Форматы JPG/WebP/AVIF; для кадров истории подойдёт вертикаль примерно 3:4 или 4:5, для главного фото — горизонталь или вертикаль, обрезка по центру. Не добавляйте в публичный репозиторий приватные материалы клиентов.

## 3. Форма связи (письма приходят на почту)

GitHub Pages — статический хостинг, поэтому письма отправляет внешний сервис форм. Он принимает сообщение с сайта и пересылает его на вашу почту. Нужен один адрес, **ничего не вставляется в код**.

**Вариант 1. Formspree** (адрес почты не виден на сайте).
1. Зарегистрируйтесь на <https://formspree.io/>, создайте форму и укажите свою почту.
2. Скопируйте адрес вида `https://formspree.io/f/xxxxxxxx`.
3. Pages CMS → **Контакты, фото, имя** → **Адрес формы связи** → вставьте адрес → сохраните.

**Вариант 2. FormSubmit** (без регистрации). Адрес: `https://formsubmit.co/ajax/ВАШ_EMAIL`. При первой отправке придёт письмо с подтверждением: подтвердите его один раз. Минус: почта окажется в адресе формы, то есть в коде страницы, и её могут собрать спам-боты.

Что делает форма:
- Посетитель указывает имя, способ связи (email, Telegram или WhatsApp) и, если хочет, пару слов. Если он оставил email, ответ в письме можно отправить кнопкой «Ответить».
- Скрытое поле-ловушка отсеивает ботов.
- Если адрес формы ещё не задан, но указан email, форма откроет у посетителя почтовую программу с готовым письмом. Если нет ни того ни другого, она вежливо попросит написать напрямую.
- Адрес формы должен начинаться с `https://`, иначе сборка проигнорирует его и напишет предупреждение в лог.

Данные посетителя проходят через стороннего оператора форм, поэтому под формой стоит пометка не писать чувствительные сведения. Проверьте условия выбранного сервиса и требования вашей страны.

## 4. Добавление статьи

1. Pages CMS → **Статьи / Articles** → **New**.
2. Заголовок, **URL slug** (латиница и дефисы), язык, дата, анонс, при желании категория и обложка.
3. Текст в визуальном редакторе. Включите **Опубликовано** только когда текст готов.
4. После сборки появятся отдельная страница, архив выбранного языка и раздел «Заметки» на главной.

Переводы — отдельные записи (`lang=en`, `lang=fr`). В комплекте есть одна неопубликованная демонстрационная статья.

## 5. Контакты и готовность к индексации

- WhatsApp: номер только цифрами, с кодом страны, без `+`: `491234567890`.
- Telegram: username без `@`.
- Public site URL: можно оставить пустым для обычного GitHub Pages. Для своего домена укажите полный HTTPS-адрес.

**Безопасный старт:** пока включено `publish_ready: false`, страницы закрыты от поисковиков (`noindex`, `robots.txt`). Когда имя, фотографии и тексты проверены, включите **Готов к индексации** и сохраните. Сайт при этом доступен по ссылке в любом режиме.

## 6. Структура кода

```text
docs/CONCEPT.md            Замысел сайта: принципы, порядок блоков, язык движения
.pages.yml                 Формы редактора Pages CMS
.github/workflows/deploy.yml  Сборка и публикация
content/
  site.json                Имя, контакты, адрес формы, фотографии
  home_ru.json             Тексты главной (сгруппированы по блокам)
  home_en.json
  home_fr.json
  posts/*.md               Статьи
media/                     Загруженные фотографии
scripts/build.py           Генератор HTML
scripts/test_build.py      Проверки
templates/index.html       Разметка, стили и скрипт главной (без текстов)
requirements.txt           Зависимости Python
```

В шаблоне нет текстов: у каждого элемента атрибут `data-i18n="группа.ключ"`, а сам текст берётся из `content/home_*.json`. Короткие служебные подписи (подсказки для скринридеров, сообщения формы, названия тем) лежат в словаре `UI` в `scripts/build.py`. Тест `scripts/test_build.py` проверяет, что для каждого ключа шаблона есть текст на всех трёх языках и что `.pages.yml` совпадает с JSON-файлами. Если вы добавили поле только в одном месте, сборка в GitHub Actions остановится и покажет, где именно.

## 7. Проверка локально (необязательно)

```bash
python -m pip install -r requirements.txt
python scripts/build.py
python scripts/test_build.py
```

Результат — `_site/index.html`. Для обычной работы через CMS локальные команды не нужны.

## 8. Что нужно знать

- На GitHub Pages нет PHP, базы данных и закрытой админки: редактор меняет файлы в GitHub, а Actions публикует статический результат.
- Изменения видны после успешного завершения workflow, обычно через минуту-две.
- Не редактируйте `_site/`: сборка перезаписывает его.
- Анимации отключаются при `prefers-reduced-motion`: цитаты просто показываются сразу. Без JavaScript страница остаётся читаемой.
- После публикации проверьте сайт на телефоне, ссылки, форму (отправьте себе тестовое сообщение) и юридические требования вашей страны.

Документация: [Pages CMS](https://pagescms.org/docs/quick-start/), [GitHub Pages custom workflows](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## 9. Дизайн: токены и формы

Весь CSS в одном блоке `<style>` файла `templates/index.html`. Цвета заданы переменными в начале. Фоны секций: `--abyss`, `--deep`, `--teal` (тёмные) и `--frost`, `--ice` (светлые); акценты синий и зелёный. Углы прямые: тест не пропустит `border-radius`. Холодная подкраска фото: `--photo-grade` (0 выключает). Переключателя светлой и тёмной темы на главной больше нет: тон секций задают фоны (`.band-deep`, `.band-teal`, `.band-frost`, `.band-ice`); тема остаётся только на страницах статей.

Логотип и favicon — встроенный SVG в `templates/index.html`; `scripts/build.py` подставляет их и на страницы статей.

- Все тексты по-прежнему в **Pages CMS** (`Тексты сайта · …`), поля идут в порядке страницы.
- Кнопка «Сейчас я не чувствую связи» **не закрывает вкладку** (браузеры этого не позволяют). Она показывает спокойное окно: «завершить визит» или «продолжить знакомство». Выбор нигде не сохраняется и не отправляется.

- Что ещё нужно подтвердить или заполнить (стоимость, формат, конфиденциальность, юридические данные, фото без водяных знаков) — в [`docs/CONTENT-REVIEW.md`](docs/CONTENT-REVIEW.md).
- Форму связи по-прежнему нужно подключить (раздел 3 выше). Пока адрес формы пуст, сайт честно пишет, что форма не подключена, и не делает вид, что отправил сообщение.
